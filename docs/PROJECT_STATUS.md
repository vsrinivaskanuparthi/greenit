### Implemented

- **Home / Use EcoLens / How it works only** in the main navigation. EcoLens Airbus title/subtitle, original local Airbus wordmark, compact typography and one report inside the upload workflow. Related file-read findings are grouped visually; full original findings stay exported. Few cards, expandable details and three-significant-figure units replace the long compute presentation.
- Source uploads accept one JS/TS/JSX/TSX (1 MiB) or ZIP (existing extraction limits), optionally alongside a HAR. Source-only results show the requested missing-traffic message, never invented emissions. Single-file/ZIP findings agree. CLI/import/historical screens remain behind an advanced link.
- HAR 1.1/1.2 (10 MiB / 5,000 entries) uses encoded `response.bodySize` only. Missing/−1 is not zero; invalid sizes, explicit cache/service-worker hits and network failures are excluded; known HTTP error bodies remain included. Decoded text/content size, header-inclusive transfer totals and session totals are never substituted. Raw HAR is never saved. URL/path/query, headers, cookies, bodies, IP and timing fields are discarded; persisted request ordinals/method/status/byte evidence/reasons are allowlisted.
- Common server-side `traffic.ts` reuses the existing CO2 adapter: **@tgwf/co2 0.18.0, explicit SWD v4, perByte(bytes, false)**, offline global defaults. Library/model versions, bundled constants, source/check date, scope and raw evidence/full precision are saved. CO2.js models broader web infrastructure through a byte proxy; neither electricity measurement nor whole-application carbon is claimed. Localhost/intranet inputs are clearly reference scenarios; no compute estimate is added.
- Actual installed parser is **@babel/parser 7.29.9**, with **@babel/traverse 7.29.8**, reported by the backend. Six reliable existing rules are retained rather than inventing broad payload/database-frequency detection. Generic HAR-to-source mapping is not guessed. The sample's known products handler is explicitly linked as an endpoint-level improvement, without grams per source line.
- Downloadable **120-line plain JavaScript server.js** and ZIP in `examples/ecolens-express` / `examples/generated/ecolens-express.zip`: synthetic catalogue, reference file, real SQLite seeds/queries, separate loopback stock mock service, validation/error handling, detail/order/quote endpoints and improved field-selection/cache variant. ZIP includes dependencies and README.txt setup. No sleeps, busy loops or inflated fixture records.
- Try Express example adapts the existing benchmark/target runner and shares its worker scheduler. Only fixed trusted catalogue selectors execute, with source/data manifest verification. Six real target processes (three alternating repetitions per version), full warm-up, fixed seven-request journey at concurrency one. Every product record/required field, complete detail, order lines/total, reference and stock result is checked. No records are skipped to manufacture savings. Actual client-facing response-body bytes feed CO2.js. Failure prevents a completed comparison. Original runtime/ZIP controls remain; new temporary source/SQLite files are cleaned.
- Optional small Request → response data → estimated CO₂e illustration has pause, static text and reduced-motion support. No fake traces/counters. File-cache improvements remain explicitly unquantified when bytes are unchanged.

## Prior browser-first compute workflow — completed, superseded above

The clarified primary requirement is now implemented end to end, reusing the existing benchmark. No new development phase or competing runner was introduced. Existing scans, SQLite data, schema 1.0, genuine local Airbus branding and the previous terminal benchmark artifact are preserved.

- **One action:** Overview or Analyse application → **Analyse Express example**. A strict fixed-sample POST queues the trusted source; the shared scheduler forks a separate worker, runs the scanner and standard before/after workload, calculates the scenario, persists it and presents results without carbon fields or terminal commands.
- **Real stages:** Reading source → Checking code → Running sample workload → Estimating carbon → Results ready, plus queued/failed states. Indeterminate progress, durable stage history, actionable retry and saved-result selection are implemented. Browser jobs are retained individually in SQLite rather than overwriting the previous terminal artifact.
- **Exact ZIP support:** Analyse application offers source inspection and a downloadable sample ZIP. Safe extraction, full file-path/content SHA-256 verification against an application-owned manifest, and atomic scan/job linkage recognise only the exact example. Extra/modified/missing files or symlinks fail recognition. Only the trusted bundled copy executes. Unrecognised uploads retain static findings and explicitly state that automatic carbon estimation is unsupported; they receive no example carbon numbers.
- **Execution controls:** ZIP and benchmark workers share one execution slot. Direct example starts are single-flight. The benchmark has a 90-second scheduler deadline plus worker watchdog; POSIX process-group termination cleans up descendants on timeout/shutdown, and parent disconnect terminates the worker. Interrupted jobs become failed on restart. Deletion guards active linked workloads and cascades finished linked results. No user path, arbitrary command or custom workload can be supplied to the browser execution endpoint.
- **Carbon first:** “Scenario CO₂e per 1,000 successful requests” and immediate scope, before/after means, differences where valid, full variability/failures, CPU/duration/memory/body bytes, source finding/fix and expandable methodology. Direction follows actual measurements. Overlapping ranges are labelled inconclusive; failed/incompatible comparisons and zero-baseline percentages remain suppressed.
- **Honest method:** centrally versioned illustrative 10 W / 400 gCO₂e/kWh allocation scenario, unchanged and explicitly hypothetical. No accessible application energy measurement was established; CPU is not electricity. Formula, provenance/date, parameters and operational-only boundary appear under How this was calculated. CO2.js is intentionally not applied to loopback body bytes because they do not represent its internet-delivery boundary; the reason is visible. No models are summed.
- **Visual explanation:** local SVG/CSS illustrates request → handler → file/CPU work → energy demand → estimated CO₂e, with distinct repeated-read/parse and cached-reuse diagrams. Explicit illustration label, static text equivalent, pause control and reduced-motion support; no fabricated counters or live-trace claim.
- **Navigation:** Overview, Analyse application, Results/comparison, Help. CLI and report import are under Advanced options in the ZIP section. Existing manual carbon forms are retained only in collapsed Advanced diagnostic tools. Help and README explain the browser-first story in plain language.
